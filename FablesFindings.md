## 0. Historical snapshot: what this was and the verdict

Plastiq is a browser-based parametric CAD studio: sketches feed a feature timeline that a geometry worker replays through a vendored OpenCascade (OCCT) WASM kernel; assemblies solve mates over the result; the document lowers to a simulation manifest; and an ML wing (AI part generation, photos → point cloud → mesh → B-rep reconstruction/NURBS fitting) lands its output back into the same parametric document as `importStep` features.

**The 2026-07-23 verdict in three sentences.** The kernel operation layer was real, broad, disciplined about memory, and heavily tested against actual OCCT — 22 document feature types executed, and the modeling vocabulary (extrude/revolve/loft/sweep/booleans/fillet/chamfer/shell/draft/patterns/mirror/primitives/STEP-IO) was genuinely implemented, not stubbed. At that snapshot, the most consequential defect was **selection persistence**: production reference-authoring paths stripped the kernel's analytic signatures. The current worktree has repaired that path plus rollback authority, Simulate failure recovery, pick remapping, and strict selection modes; use the current ledger above rather than this historical verdict for status.

**Composition model.** Every op returns a new `Solid` (Copy=true transforms, NonDestructive booleans). Feature composition happens in the app's rebuild loop, not the kernel — `unionAll` at `apps/plastiq/src/worker/rebuild.ts:167`, `makeCompound` at :212, mirror-feature = kernel `mirror` + `union` at :1025. A "hole" is app-level extrude+cut (rebuild.ts:142), not a kernel op. Booleans always run fuzzy(1e-7) → NonDestructive → Build → `UnifySameDomain` (boolean.ts:150-169) — load-bearing for FaceRef persistence, proven in `boolean.test.ts:125-146`.

**Units and errors.** The kernel is SI metres throughout; STEP/IGES compensate for OCCT's mm declaration by scaling shapes ×1000/÷1000 because the wasm's `Interface_Static` exposes no statics (io/index.ts:27-31; pinned in `oc/bindings.test.ts:107-123`). OCCT `Standard_Failure` reaches JS as a raw C++ pointer; `describeOcctError` can only produce one generic sentence (`oc/error.ts:43-58`, pinned in bindings.test.ts:223-238) — so unvalidated inputs that reach OCCT fail _opaquely_, never silently.

**Memory discipline.** The dominant pattern is rigorous: trash-array + reverse-order `finally` in every action (extrude.ts:65-95, revolve.ts:43-67, transform.ts:61-82), ownership-null handoff in extrudeToFace (:363, :441), null-`Shape()` handles freed before throws, `Solid.delete()` double-free guarded (solid.ts:24-28), io writers/readers freed in `finally` (io/index.ts:93-97, :134-137, :163-167). The cleanup contract is itself unit-tested (`cleanup.unit.test.ts`, `errorpaths.cleanup.unit.test.ts` — honestly labeled mock-kernel).

### 1.2 Kernel defects (each verified at the cited line)

- **K1 — Chamfer silently drops `distance2`.** `twoDist` requires `opts?.face != null` and `d2 !== distance` (`action/dressup.ts:99-100`); without a face the code emits a symmetric chamfer via `Add_2` (:116) and reports success. An asymmetric-chamfer request degrades silently. No test covers the without-face case.
- **K2 — Shell tolerance hardcoded at `1e-3` m (1 mm)** (`action/dressup.ts:206`) — three orders coarser than the kernel's own 1e-7 boolean fuzzy contract; `boolean.ts:73-75` itself refers to this value as a defect, yet it ships.
- **K3 — Stale load-bearing comment in `io/index.ts:64-65`** claims `BRep_Builder`/`TopoDS_Builder` are "unbound in the trimmed wasm … a hand-built compound is not an option" — directly contradicted by `makeCompound` constructing `new oc.BRep_Builder()` (`solid/solid.ts:101-102`) and by `bindings.test.ts:156-160`.
- **K4 — `unifySameDomain` swallows all failures** (`action/boolean.ts:118-121`, bare `catch { return shape; }`): the boolean silently degrades to the fragmented result — exactly the state the module header (:13-21) says breaks coplanar face selection — with no signal in `BooleanResult`.
- **K5 — `exportForSim` silently omits geometry-less bodies** (`lower/export.ts:54`, `if (!solid) continue;`): a mis-wired `Body` vanishes from the SimManifest without error.

### 1.3 Assembly solver (what it actually is)

Solves six **mate** kinds — coincident, concentric, parallel, perpendicular, distance, angle (`assembly/solver.ts:36-42`). `JointKind` (revolute/prismatic/cylindrical/fixed/ball/planar, :44-50) is **never solved** — it is vocabulary lowered 1:1 into the sim manifest (`lower/joints.ts:31-38`). Algorithm: Levenberg–Marquardt over 6-DOF poses of non-fixed components; forward-difference numeric Jacobian (eps 1e-7, :169), additive λ·s·I damping scaled by max JᵀJ diagonal (:275-288), partial-pivot Gaussian elimination (:186-205), λ∈[1e-9, 1e6] (:294-299), 200-iteration cap (:259). DOF = 6·free − numeric rank (tol 1e-6, :304-306); verdicts split over-constrained vs non-converged via RESIDUAL_TOL 1e-5 / GRADIENT_TOL 1e-7 (:307-323).

## 4. Selection & context — the accuracy question

This is the investigation's central finding: the kernel implements a two-tier persistent-reference system, and production only ever uses the weak tier.

### 4.1 How identity works (kernel)

There is **no OCCT topological naming and no shape-history tracking**. `BRepTools_History` is bound for exactly that purpose (`occt.build.yml:114-122`) and never called; the OCAF/TNaming stack is absent from the wasm entirely (§2.3). Identity is geometric-signature re-matching:

- Tessellation assigns transient sequential ids (`mesh/tessellate.ts:96-159` faces, :242-248 edges, :281-287 vertices) — documented stable-within-one-mesh only (`mesh/tagged.ts:67, 91-95`).
- Persistent signatures captured per entity: faces get an area-weighted `normal` (`mesh/normals.ts:73-96`), GProp `centroid` (:147-155), and the **primary analytic `surface` signature** read off the B-rep (`BRepAdaptor_Surface`, `mesh/surface.ts:103-181` — plane/cylinder/cone/sphere/torus parameters). Edges get adjacent-face `faceNormals`, `faceSurfaces`, and a mid-parameter `midpoint` (tessellate.ts:240-259). The type comments are explicit that `surface`/`faceSurfaces` are the PRIMARY signatures and normal/centroid are back-compat (`tagged.ts:21-59`) — a plain normal is "meaningless floating-point residue" for a closed curved face.
- **Vertices have no reference type at all** — `VertexPoint` is id+position (`tagged.ts:101-105`); no `VertexRef`, no resolver anywhere.

### 4.2 The analytic-signature path is dead code in production

Every production constructor of a reference strips the primary signature:

- The worker transfer drops `faceSurfaces` from edges (`worker/geometry.worker.core.ts:39-45` — the edge object carries only edgeId/positions/faceNormals/faceIds/midpoint), so the main thread can never recover them.
- The Viewport builds `selectionRefs` keeping only `{normal, centroid}` for faces and `{faceNormals, midpoint}` for edges (`three/Viewport.tsx:265-278`) even though `built.faceGroups[].surface` arrives intact in the same payload.
- Kernel selectors strip them too: `faceRef = {normal, centroid}`, `edgeRef = {faceNormals, midpoint}` (`select/predicates.ts:97-98`).
- The AI's `inspectGeometry` emits the same degraded form (`ai/tools/inspectGeometry.ts:237, 245`).

Grep confirms zero non-test constructions of a ref carrying `surface:`/`faceSurfaces:`. Consequence: every UI- or AI-picked fillet/shell/extrude-to-face on a curved face (hole wall, boss, fillet blend) is persisted with exactly the signature the kernel's own comments (`surface.ts:1-32`) document as guaranteed to break on the first upstream parameter change. The analytic path is proven only by kernel tests that hand-build refs (`mesh/surface.test.ts:110-155`).

### 4.3 Resolution behavior and its cliff

- `resolveFaceRef` (`mesh/resolve.ts:46-94`): with `ref.surface` → `surfacesMatch` filter, nearest-centroid tiebreak; without → legacy `dot(normal) ≥ 0.999` (:26, :71-76). Distance capped at the bbox diagonal (:89-93) → `null` (fail-loud). `resolveEdgeRef` (:122-168) mirrors this over edge→face ancestor maps.
- **No surface→legacy fallback**: a surface-bearing ref whose face merely _moved_ (plane offset, hole translated) fails the 1 µm/0.26° `surfacesMatch` tolerances (`surface.ts:184-205`) and resolves to null (`resolve.ts:59-68` — non-matching faces are `continue`d) — contradicting the parametric-tracking intent stated in the module's own centroid-cap comment (:100-105). Latent today only because production never sends surface-bearing refs (§4.2).
- Failure contract downstream is loud: dress-ups throw "`N of M selected edge(s) did not resolve`" (`action/dressup.ts:59-65, 125-131, 181-187`) — no partial dress-ups. But "other" surfaces (all B-splines) match by enum tag alone (`surface.ts:266-271`), and surface-refs without centroid tie-break on OCCT enumeration order (resolve.ts:68, :141).

### 4.4 Interactive picking (verified accurate)

The pick pipeline is genuinely face/edge/vertex-capable: one render group per B-rep face with `userData.faceIds` (`viewport/buildMesh.ts:66-72`), per-edge `LineSegments` (:94-95), corner `Points` (:120); raycast → `faceIndex` → group range → faceId (`viewport/pick.ts:21-31, 89-122`); thin-target fallback via 14 px screen-nearest candidates (`three/Picking.tsx:283-304`) and a GPU color-id pick (`three/gpuPick.ts:46-108`). Selection state is `picks: Pick[]` of transient ids (`store/types.ts:141-144`) bridged to persistent refs via `selectionRefs` rebuilt after every build (Viewport.tsx:261-281). Feature builders consume refs, not indices (`viewport/dressup.ts:17-138`). Wrong-kind selections are validated to status messages, not crashes (`three/contextmenu/config.ts:99-115`; `actions/registry.ts:942-945`).

### 4.5 Selection/context defects

- **S1 — Rebuilds never invalidate `picks`.** A build replaces `selectionRefs` (Viewport.tsx:278) but `picks` is cleared only by `loadDocument`/`reset`/`clearPicks` (store.ts:367, :455, :644). - **S4 — Mate picks mislocalize on exploded assemblies.** The click hits the rendered (exploded) pose (Viewport.tsx:38-51, :375-378) but `addMatePick` runs `worldToLocal` against the document pose (store.ts:721-722); nothing blocks mate mode while `explodeFactor > 0` (AssemblyTree.tsx:295-317).
- **S5 — Stale `matePicks` after instance removal.** `removeInstance` filters mates/joints but not `matePicks` (store.ts:670-683); `applyMate` has no existence check (:729-754); `toMateRef` then emits `component: -1` into `solveMates` (`assembly/model.ts:247-254, 267-281`) — which itself has no bounds check (K9). `applyJoint` checks only the parent (store.ts:770-775).
- **S6 — Silent drop in `addMatePick`** when the faceId has no ref or the instance is gone (store.ts:718-719) — the "Picking n/2" counter just doesn't advance.
- **S7 — Sketcher "Look At" ignores the actual sketch plane** — hardcoded direction `[0,-0.5,1]` despite `resolvedFrame` being available in the same store (Sketcher.tsx:748-763; the comment admits it).
- **S8 — Context menus execute against an open-time snapshot** (`useCanvasRightClick.ts:130-138`) — a rebuild completing while a menu is open leaves `ctx.refs` stale (narrow race, same class as S1).
- **S9 — `e2e/plastiq/zz-p2.spec.ts` is an assertion-free debug probe** (console.log only, :21), staged as a new spec.

### 4.6 Sketch context (including the uncommitted working-tree change)

Plane derivation is sound: `enterSketch` (`sketch/sketchStore.ts:212-230`) with the world frame resolved via worker `facePlane` and a stale-async guard (Viewport.tsx:328-364); default planes auto-land on the outermost face (`sketch/defaultPlane.ts:56-93`).
